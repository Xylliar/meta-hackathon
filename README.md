# Tempo

**15 minutes a day to walk into every exam prepared.**

Tempo is a revision app for students. Snap photos of your course notes, add your exam dates, and Tempo turns them into a clean course to read, flashcards and a quiz, then plans **15 minutes of revision a day** until each exam. Miss a day and the plan is rebuilt over the days that are left.

The content is generated by **Muse Spark 1.3** through the Meta Model API. Tempo was built by **Adrien JACQ** for a Meta hackathon.

> The app's interface is in French; this README and the demo videos are in English.

## Why Tempo

Most students revise by rereading their notes, although research shows it is one of the least effective methods:

- In a survey of 177 university students, 84% reread their notes, and only 11% tested themselves (Karpicke, Butler & Roediger, 2009).
- Students who practised recalling a text remembered 61% of it a week later. Those who only reread it remembered 40%, although they read it four times as often (Roediger & Karpicke, 2006).
- With flashcards, spreading reviews over time beat cramming for 90% of learners (Kornell, 2009).
- A review of ten study techniques rates only two as high utility, practice testing and spaced practice. Rereading and highlighting rate low (Dunlosky et al., 2013).

The goal was to make the effective method the easy one. A student should only have to bring their notes and an exam date. Tempo then provides the testing (flashcards and a quiz) and the spacing (a daily plan).

## What was built

- **Course from photos:** use the camera or the gallery. Muse reads handwritten or printed notes and returns a structured course: definitions, formulas, key points, examples and classic traps, with key words in bold and a 30-second summary.
- **Flashcards that follow good practice:** one idea per card, a short answer, and a diagram, memory trick or example when it helps. Cards stay faithful to the notes, and formulas are written in plain symbols.
- **Revision sessions:**
  1. Read the course.
  2. Do the flashcards, graded *I know it* or *I don't know it*. A card you don't know comes back a few cards later, until it sticks.
  3. Take a short quiz. A wrong answer is explained and becomes a new flashcard.
- **Spaced repetition:** known cards come back after 1 day, 3 days, a week, and so on, always before the exam.
- **Adaptive planning:** the planner fits new parts, new cards, reviews and quiz questions into the daily budget. It keeps the last day for a final review and re-plans instantly when a day is skipped.
- **Weekly timetable:** you can enter your weekly class timetable in the Planning page.
- **Accounts:** each account keeps its own data. Settings include light, dark or automatic theme.
- **A reminder that Tempo doesn't replace exercises:** flashcards and quizzes help you remember, exercises help you understand.

Scheduling is not left to the AI. It is plain, deterministic code covered by automated tests, so re-planning is instant and reliable. The model only reads the photos and writes the content.

## Running it locally

### Requirements

- **Node.js 20.9 or later** and npm.
- **Optional:** a **Meta Model API key**, created on the "API keys" page of the Meta Model API. Without a key, Tempo uses a mock model that returns sample content, and the header shows an "IA : démo" badge. Everything else works the same.

### Steps

```bash
git clone <this repository>
cd meta-hackathon
npm install
cp .env.example .env    # then put your key in MODEL_API_KEY
npm run dev
```

Open http://localhost:3000, create an account, then either:

- **Add a course:** open the **Cours** tab, then enter a subject, an exam date and photos of your notes. JPG, PNG or WebP only; the API does not accept HEIC.
- **Load sample data:** click **Charger la démo** on the home page to get three subjects with courses, cards and exams.

**Trying the planning over several days:** the home page has a **Jour suivant** button that simulates the next day.

**Trying it on your phone:** open the app from a phone on the same Wi-Fi, at `http://<your computer's IP>:3000`.

### Configuration

| Variable | Purpose |
|---|---|
| `MODEL_API_KEY` | Meta Model API key. `API_KEY` is accepted too. Never commit it: `.env` is ignored by git. |
| `MUSE_MODEL` | Optional. The model to call (default `muse-spark-1.3`). Avoid variants that train on inputs, since students' notes would be shared. |
| `TEMPO_DATA_DIR` | Optional. Stores data in another folder instead of `data/`, which is handy for demos and screenshots. |

### Other commands

```bash
npm test        # 44 unit tests (planner, spaced repetition, actions, prompt parsing, accounts)
npm run lint
npm run build && npm start   # production build
```

## How it works

| Path | Role |
|---|---|
| `src/lib/llm/prompt.ts` | The prompt and JSON schema sent to Muse, plus validation of its answer. The quiz returns the right answer as text and the app shuffles the choices, so the model never points at a wrong option. |
| `src/lib/llm/muse.ts` | The call to the Meta Model API (`/v1/chat/completions`, images as base64, strict JSON schema output). `mock.ts` is the fallback model. |
| `src/lib/scheduler.ts` | The planner: spreads reading, new cards, reviews and quiz questions before each exam within the daily budget. A pure function, recomputed on every change. |
| `src/lib/srs.ts` | Spaced repetition: the interval ladder and Leitner boxes, with reviews always moved before the exam date. |
| `src/lib/actions.ts` | Every change to the data, as a pure reducer. |
| `src/lib/store.ts` | Local JSON storage: `data/users/<id>/db.json` per account, `data/uploads/` for photos. |
| `src/lib/auth.ts`, `accounts.ts`, `password.ts` | Accounts: passwords hashed with scrypt, sessions in an `httpOnly` cookie. Only a hash of the session token is stored. |
| `src/app/` | Pages (Connexion, Accueil, Cours, Planning, Séance, Paramètres) and API routes. |

Built with Next.js 16 (App Router), React 19, Tailwind CSS 4, TypeScript and Vitest.

Data is stored as local files. That suits a hackathon project or a single machine, but a real deployment would need a database.
